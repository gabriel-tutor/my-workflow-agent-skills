# 08: Installer that tells the truth

**What to build:** On a new machine the one-command install either succeeds or says exactly why it did not, and it changes nothing but the plugin list. The installer checks the `claude` CLI, Node, and `python3` at 3.9 or newer (naming the version found when too old); installs Matt Pocock's skills through skills.sh when missing; adds the marketplace, installs, updates and enables the plugin, stopping with a message the moment any `claude plugin` command fails; no longer writes settings.json at all (no Read rules, no backup); keeps the optional Superpowers disable; and prints the tested platforms and the next steps. `docs/compatibility.md` records the tested combinations: operating systems, Python, Claude Code version, Matt Pocock's skills commit and file hashes, Superpowers version alongside. The README's install section matches.

Facts the CLI settled (2.1.272): `plugin install` leaves a fresh install enabled, and `plugin enable` exits 1 with "already enabled" on an enabled plugin (`disable` likewise on a disabled or absent one); `marketplace add` and `plugin install` exit 0 when already done; the `claude plugin` commands themselves record the marketplace and the enabled plugin in the config dir's settings.json (`extraKnownMarketplaces`, `enabledPlugins`). So the first criterion's "issues ... enable" holds as: enable is issued when `plugin list` says disabled (suite case 6), never after a fresh install; the spec's Testing Decision 4 reads the same way. skills.sh 1.5.26 installs into the current project without `-g`, so the hook's old advice sent a user to the wrong place; the one command now named in the hook, the installer and the README is `npx skills add mattpocock/skills -g -a claude-code`. A directory-marketplace install lands in the config dir's plugin cache with the commit SHA recorded, while a session's `CLAUDE_PLUGIN_ROOT` still points at the clone.

Review found and fixed: `plugin list` and `marketplace list` ran outside the failure helper, so a failing list left the installer to guess (now every `claude plugin` call runs through `claude_plugin`, which keeps the output for the parsers and stops with the real error; two new cases); a non-version `python3 --version` (a pyenv shim) died with an unbound-variable error instead of the message; the Superpowers step read a status from the wrong output (caught by the suite); the three spellings of the install command (the hook's trailing clause shortened to "and restart" to keep the partial-install injection at 2,898 bytes on the 120-character guard); `plugin()` beside `PLUGIN`; the stub's dead argument; the trailing space in the missing list; the fourth copy of the skill list unpinned; two wording greps; the closing line's pointer without OS names or a URL.
